# Продуктовый харнесс · версия 1

Идея → разговор с автором → сбор по каждой работе → сверка цитат → рынок и карта сегментов → проверка свежим агентом → карточка решения.

Ты — главная сессия. Шаг 0 ведёшь сам, шаги 1, 3, 4 и 5 отдаёшь агентам, шаг 2 делает скрипт. Каждый шаг читает файлы и пишет свой файл, поэтому любой шаг можно перезапустить отдельно. После каждого шага решает человек: ты показываешь итог и ждёшь его «да» или правки. Всё, что происходит, идёт в журнал.

В этой версии нет отсева сегментов, агента-обвинителя и пар «сегмент × вариант»: карточка отвечает по идее целиком.

## Перед запуском

- Прочитай этот файл целиком.
- `SKILL` — абсолютный путь папки, где лежит этот `SKILL.md`. Пути `$SKILL/tools/…`, `$SKILL/references/…` и `$SKILL/ui/…` ниже — от неё. В командах подставляй путь целиком: переменной `SKILL` в shell нет.
- Прогон идёт в папке сессии — там, где её открыли; команды запускай из неё. Git прогону не нужен: ворктри, ветки, коммиты, пуши и PR не заводи. Запись прогона — стенд (раздел «Стенд»).
- `RUN` — папка `runs/<ГГГГ-ММ-ДД>-<идея>-<кто>/` в папке сессии. Создай её, положи вход автора как есть в `RUN/input.md`, заведи журнал по разделу «Журнал» и `status.json` по разделу «Страница прогона» (шаг `brief` — `running`) и сразу отправь прогон на стенд.
- Потом проверь `python3 -c "import yaml, bs4"`. Ошибка — попроси человека выполнить `python3 -m pip install --user pyyaml beautifulsoup4` и жди: без этих пакетов не работают снимки шага 1 и сверка шага 2. Pip пишет `externally-managed-environment` — та же команда с `--break-system-packages`.
- `<идея>`, `<кто>`, имена файлов работ и сегментов — латиницей, строчными, через дефис: `2026-10-01-bali-tax-lena`, `bali-tax-report.md`. Эти имена уходят в ссылки страницы.
- Имени ведущего в сообщении нет — в имени папки пиши `anon`, а имя спроси первым вопросом шага 0 и впиши в «Ведёт:». Папку потом не переименовывай. Нет блока «Вход:» — в `input.md` идёт всё сообщение автора без слов о прогоне.
- Методология — только канон в `$SKILL/references/nmt/`, не по памяти. Для шага 0 прочитай:
  - `$SKILL/references/nmt/Next-Move-Theory-Canon/Algorithms/the-algorithm.md`, Step 1–2;
  - `$SKILL/references/nmt/Next-Move-Theory-Canon/Advanced-Jobs-To-Be-Done/job-structure.md`;
  - `$SKILL/references/nmt/Next-Move-Theory-Canon/Advanced-Jobs-To-Be-Done/job-types-and-properties.md` §8 — ложная работа;
  - `$SKILL/references/nmt/Next-Move-Theory-Canon/Next-Move-Theory/nmt-key-theses.md` §4 — цепочка к прибыли.
- Условия использования канона — `$SKILL/references/nmt/NOTICE.md`. Ключи, токены и пароли в файлы прогона не пиши: файлы уходят на стенд.
- Во время прогона не открывай другие прогоны, `$SKILL/evals/`, `cases/`, `lab/` и `pipeline/`: чужие выводы сдвинут твои.

## Папка прогона

```
RUN/
  input.md              вход автора как есть
  author-answers.md     каждый вопрос человеку и его ответ, дословно
  brief.md              шаг 0
  evidence/<работа>.md  шаг 1, файл на работу и на каждого сборщика
  sources/              снимки: src-NNN.txt и src-NNN.yaml
  check.md              шаги 2 и 4
  segments.md           шаг 3
  card.md               шаг 5
  notes.md              журнал: кто ведёт, события, агенты, ответы, отклонения
  status.json           шаги и вопрос человеку для страницы прогона
  .stand.json           ключ записи прогона на стенде; пишет push_run.py
  ui.html               локальная страница прогона, когда стенд не отвечает
```

Перезапуск шага перезаписывает его файл, прежняя версия остаётся на стенде: он хранит каждую отправку. Снимки `sources/` на стенд не уходят и лежат только в папке прогона.

## Журнал

По журналу прогоны разных людей сравнивают и ищут, где прогон ошибся и сколько стоил. Поэтому пиши в него каждое событие из списка ниже — одной строкой, в одном формате, без пересказа файлов шагов.

`notes.md` начинается двумя строками:

```
# Заметки прогона: <идея>

Ведёт: <имя>. Движок: <Claude Code | Codex>, главная модель: <id модели>.
```

Главная модель — та, на которой идёт твоя сессия, а не догадка: она уходит в базу стенда, и по ней сравнивают прогоны. Claude Code берёт точный id модели из своего системного промпта (`claude-opus-5-5`), не псевдоним вроде `claude-opus-5[1m]`. Codex берёт значение `-m`, с которым его запустили, а без `-m` — `model` из `~/.codex/config.toml`.

Дальше — строка на событие. Формат строки: `ДД.ММ ЧЧ:ММ — шаг N — что случилось — модель — минуты — токены`. Это образец, а не строка журнала: в `notes.md` его не переписывай, пиши только настоящие события. Дата и время — с нулём впереди и по часам: `date '+%d.%m %H:%M'` даёт `01.10 09:05`. На глаз время не пиши — ни здесь, ни в `author-answers.md` и `status.json`. Модель: у агента — id модели (`claude-opus-5-5`), у скрипта — «скрипт», у человека — «человек». Минуты — целое число (`duration_ms` / 60000, с округлением), токены — только цифры, без запятых и слов; нет данных — «неизвестно». Строку в другом формате страница прогона не разберёт.

События:
- запуск агента: какой агент, по какому файлу из `references/`, куда пишет; минуты и токены — `0 — 0`;
- конец агента: итог одной фразой, минуты и токены из отчёта агента о расходе. Claude Code даёт их в уведомлении о конце агента (`duration_ms`, `total_tokens`), Codex — в событии `turn.completed` своего JSON-вывода: токены = `input_tokens` + `output_tokens`. Не видно (так в сессии Codex без JSON-вывода) — «неизвестно»;
- ответ человека: `<имя>: «<слова дословно>»; <что решено>`, модель — «человек», `0 — 0`;
- вопрос шага 0, снятый проверкой ценности: `снято проверкой: <вопрос>; <почему>`, модель — id твоей модели, `0 — 0`;
- каждый запуск сверки цитат брифа: `сверка брифа: <строка «Цитаты брифа»>`, модель — «скрипт», `0 — 0`;
- перезапуск шага, сбой агента, ссылка стенда, ошибка отправки на стенд;
- отклонение от этого файла — что сделал иначе и почему; поломка скилла — какое правило или скрипт подвёл и как.

`author-answers.md` — каждый вопрос, который ты задаёшь человеку, и его ответ, дословно и со временем. Короткое «да» — тоже ответ.

```markdown
**Вопрос (ДД.ММ.ГГГГ ЧЧ:ММ, шаг N):** <вопрос, как ты его задал, с вариантами>
**Ответ (ЧЧ:ММ):** «<слова человека>»
```

## Остановка после шага

Остановок пять: после шага 0, после шагов 1 и 2 вместе, после шага 3, после шага 4 и после шага 5.

На каждой остановке:

1. Обнови `status.json`: итог шага, шаг в `waiting`, вопрос в `question`. Отправь прогон на стенд (раздел «Стенд»).
2. Покажи итог в 3–5 простых фразах: что вышло, главные числа, что спорно, чего не хватило. Дай путь к файлу шага и ссылку на страницу. Спроси: «да» или правка? Вопрос запиши в `author-answers.md`.
3. Жди. Следующий шаг начинай только после явного «да».
4. Ответ запиши дословно в `author-answers.md`, строкой в `notes.md` и в `answers` в `status.json`; там же `question: null`, а после «да» шаг — `done`, следующий — `running` со `started`. Отправь прогон на стенд.
5. Правка — перезапуск этого шага. Шаг 0 правишь сам: новая версия брифа. Шаги 1, 3 и 5 перезапускает новый агент с прежним сообщением и добавкой в конце: «Правка человека: «<слова дословно>»». Правка после шага 4 — перезапуск шага 3 (раздел «Шаг 4»). Не пересказывай: пересказ теряет смысл, а журнал должен показать, что человек просил. После нового сбора снова запусти шаг 2. После перезапуска — снова остановка.
6. «Да» с правкой («давай, только …») — перезапусти шаг с правкой, одной фразой скажи, что изменилось, и иди дальше.

## Стенд

Стенд — сайт команды, где лежит каждый прогон: его страница и общий список прогонов. Отправка на стенд:

```bash
python3 $SKILL/tools/push_run.py --run RUN
```

Скрипт шлёт `status.json`, файлы шагов, `input.md`, `author-answers.md` и журнал и печатает ссылку на страницу прогона. Первая отправка заводит прогон и кладёт ключ записи в `RUN/.stand.json`, следующие обновляют ту же страницу. `.stand.json` не копируй в другой прогон и не удаляй, кроме ошибки 403 ниже: без ключа стенд заведёт новую страницу, с чужим — откажет.

Когда отправлять:
- сразу после `input.md`, первых строк журнала и `status.json`, до проверки пакетов и брифа: скрипту нужен только `python3`, а без `status.json` он прогон не отправит;
- на каждой остановке — после вопроса и после ответа человека (раздел «Остановка после шага»);
- при запуске шага без остановки перед ним (шаг 2 сразу после сбора, новый круг шага 4, перезапуск шага), когда шаг уже `running` со `started`;
- после конца каждого агента, когда его строка уже в `notes.md`.

Ссылку даёт первая удачная отправка. Сразу дай её человеку отдельной строкой — в начале прогона это первая строка в чат — и запиши в `notes.md`: `ДД.ММ ЧЧ:ММ — шаг N — стенд: <ссылка> — скрипт — 0 — 0`.

Ошибка — одна строка `стенд: <причина>` и код 1. Запиши её событием в `notes.md`, модель — «скрипт», и иди дальше: прогон стенда не ждёт, следующая отправка пробует снова. Ошибка 403 («чужой прогон») сама не пройдёт: удали `RUN/.stand.json` и отправь снова — стенд заведёт новую страницу. Новую ссылку дай человеку и запиши в `notes.md`. Пока стенд не отвечает, на остановке давай вместо ссылки путь к локальной странице (раздел «Страница прогона»). Код 0 и строка `стенд: не влезли …` — отправка прошла без этих файлов: запиши строку в `notes.md`.

Человек сказал не слать прогон на стенд — `push_run.py` не запускай, на остановках давай путь к локальному `ui.html`.

Страница прогона открывается по ссылке без пароля — дай ссылку человеку сразу. Список всех прогонов спрашивает общий пароль команды; его даёт людям Андрей, ты его не знаешь и не спрашиваешь. В Codex отправке нужна сеть — раздел «Движки».

## Страница прогона

Человек следит за прогоном на странице стенда: шаги и их итоги, тексты файлов, журнал из `notes.md` и открытый вопрос. Дизайн один на все прогоны — `$SKILL/ui/page.html`, данные шлёт `push_run.py`. Отвечает человек в чате.

- `RUN/status.json` ведёшь ты. Образец — `$SKILL/references/status-example.json`: прогон на остановке после шага 3. Шагов шесть: `brief` 0 «Бриф», `collect` 1 «Сбор», `check` 2 «Сверка цитат», `map` 3 «Карта сегментов», `review` 4 «Проверка карты», `card` 5 «Карточка решения». Без `steps` скрипт подставит их сам со статусом `next`. По `check` и `review` страница показывает счёт сверки и кругов проверки.
- Скелет файла:
  ```json
  {"run": "<папка прогона>", "title": "<идея в 3–6 словах>", "updated": "ДД.ММ.ГГГГ ЧЧ:ММ",
   "steps": [{"id": "brief", "n": 0, "title": "Бриф", "status": "waiting", "file": "brief.md",
              "summary": "…", "started": "ЧЧ:ММ", "finished": "ЧЧ:ММ"}, "…ещё пять шагов…"],
   "question": {"id": "q-1", "step": "brief", "text": "…", "items": ["…"], "options": ["да", "правка"], "asked": "ЧЧ:ММ"},
   "answers": [{"id": "q-1", "step": "brief", "text": "…", "answer": "…", "at": "ЧЧ:ММ"}]}
  ```
  `status` шага — `done`, `running`, `waiting` (ждёт человека), `next` или `skipped`. `summary` — первые 1–3 фразы итога, который ты даёшь в чате. Без `run` черновики ответов разных прогонов смешаются, без нового `id` вопроса черновик прошлого вопроса всплывёт в следующем.
- Несколько вопросов сразу, как на остановке шага 0, — в `question.items`: строка на вопрос, те же слова, что в чате, но без номеров — их ставит страница. Вопрос об имени идёт в `text` первой строкой: страница показывает `text` над списком, и вопросы брифа получают номера с 1, как в чате и в `brief.md`. Отвечают в чате.
- `question` — `null` или вопрос; `question.step` — id шага в `waiting`. На остановке после шагов 1 и 2: `collect` — `done`, `check` — `waiting`. У `collect` в `files` — все `evidence/*.md`. `id` вопросов идут подряд: `q-1`, `q-2`, …
- Стенд не отвечает — собери страницу локально и дай человеку путь `file://<абсолютный путь RUN>/ui.html`. В браузере она только показывает прогон: человек отвечает в чате.
  ```bash
  python3 $SKILL/tools/render_ui.py --run RUN
  ```

## Шаг 0. Разговор с автором

Ведёшь сам, без агента и без поиска в сети.

1. Прочитай вход. Выпиши для себя, что автор уже сказал о плательщике, цели, стране, модели дохода и нынешнем решении.
2. Пересчитай числа автора. Проверь суммы, произведения и пересечения групп. `14 млн × 1%` — это 140 тыс., а не 14 тыс. `5 + 14 + 6 = 25` не доказывает, что группы не пересекаются. У каждого числа найди, кого оно считает, за какой период и откуда взято. Числа расходятся — сначала проверь, не о разных ли группах, периодах или слоях они говорят: люди и заходы, оборот и выручка. Объяснение годится, только если его даёт вход или ответ автора. Своё объяснение («$12 тыс. — это 2% с $600 тыс.») — пример ответа в вопросе автору, а не повод вопрос снять. Не объяснилось — вопрос автору. Числа во входе не правь.
3. Собери вопросы — только те, на которые нет ответа ни во входе, ни в ответах автора; каждый вопрос — одна строка с примером ответа, без вступления и пересказа входа:
   - кто платит и кто держит деньги клиента;
   - цель в деньгах к дате, или цели нет;
   - страна и покупатель;
   - модель дохода и ставка; «комиссия» не отвечает на вопрос, кто платит;
   - как клиенты решают эту задачу сейчас и сколько за это платят;
   - вопросы по числам из пункта 2;
   - развилки на пути фичи (абзац ниже).
   Пример — конкретный возможный ответ: число, имя, действие («2 млн ₽ в месяц к марту»), а не вопрос другими словами («чтобы достичь своей цели»).
   «Не знаю» — законный ответ. Он становится строкой «неизвестно», а не догадкой.
   Развилки. Пройди путь фичи по шагам: что её запускает, откуда берутся её данные, что клиент делает с результатом, что происходит потом. На каждом шаге спроси себя, как это бывает устроено в этой области по-разному и от какого варианта зависит, сработает ли фича и кому навредит. Развилка, исход которой знает только автор по своим данным и практике, — вопрос. «Какая доля X?» годится, только если ты можешь назвать два исхода развилки, которые этот ответ разделит. Развилки — главный источник сильных вопросов: вопрос о плательщике и ставке и расхождение в числах автора всегда входят в пятёрку для чата, а оставшиеся места развилки занимают раньше прочих тем.
   Каждый вопрос до брифа проверь на ценность ответа:
   - два исхода: как изменится вывод при ответе «А» и при ответе «Б»? Никак — вопрос снят;
   - эксперт: человек, который знает этот рынок и продукт, ответил бы не думая? Тогда это не вопрос, а строка гипотезы в разделе брифа «Неизвестно», как в шаблоне. Строки гипотез входят в 50 строк брифа: не влезает — пиши короче. Так же снимай вопрос, ответ на который следует из входа или из того, как устроен такой продукт, — например, для кого фича и в какой момент пути клиента она работает;
   - автору остаётся то, что знает он один: внутренние данные, принятые решения и риски, факты вне входа.
   Вопросы о плательщике, ставке, цели, стране и числах автора проверка снимает, только если ответ есть во входе или в ответах автора, и в «гипотезу» не переводит — абзац «Нельзя». Вопрос об имени ведущего она не снимает.
   Снятый вопрос — событие в журнале (раздел «Журнал»). Вопросов вышло меньше пяти — не добирай.
4. Подними идею до работы клиента: «чтобы что?» на 3–5 уровней вверх. В черновике брифа поднимай по входу сам; где вход молчит, «чтобы что?» — вопрос автору в тот же список. Остановись на одной-двух работах, за которые клиент уже платит деньгами или временем. Работа пишется так: `I want to <глагол> …, чтобы …`, после `I want to` — русские слова клиента. Шаг 1 отдаёт строку работы сборщику дословно, поэтому в ней нет заглушек, вопросов и «…»: «чтобы» из слов автора пиши как есть, выведенное из них — с пометкой «гипотеза», а выводить не из чего — убери хвост «чтобы …». Из-за неизвестного «чтобы» работу из списка не убирай. В работе нет названия продукта, его функций и технологий; слова из входа, которые описывают сам продукт, — стоп-лист. Сервис делает работу за клиента — в работе остаётся то, что получает клиент («сдать отчёт в налоговую»), а то, как это делает сервис («сводим таблицы»), уходит. Свойство решения («кошелёк, которым владею только я», «в один клик») — не работа, а критерий или решение. У каждой работы — уровень (Big или Core) и слова автора, из которых она выведена. Если автор назвал больше двух работ, пусть выберет первые две; остальные запиши в «Отложено».
5. Запиши `RUN/brief.md` по шаблону ниже сразу, ответов не жди: чего нет во входе — «неизвестно». Бриф — не длиннее 50 строк; фактов, которых нет в `input.md` и `author-answers.md`, в нём нет. Потом сверь цитаты брифа: `python3 $SKILL/tools/check_quotes.py --run RUN --brief`. Скрипт ищет каждую «цитату» вне раздела вопросов в `input.md` и в ответах автора из `author-answers.md` и зачёркивает те, которых там нет. Зачёркнутое и неточное поправь — слова автора дословно в «», свои слова без кавычек — и запусти снова, пока в строке «Цитаты брифа» не станет «Неточно: 0. Зачёркнуты: 0». Вход цитируй дословно: «неточно» бывает и у цитаты с обратным смыслом или сдвинутой запятой.
6. Остановка по разделу «Остановка после шага»: итог брифа в 3–5 фразах, путь к `brief.md` и первые пять вопросов из раздела брифа «Вопросы, от ответа на которые меняется вывод» — одним сообщением. Больше пяти вопросов человек в чате не прочтёт, остальные ждут в брифе. Вопрос об имени ведущего (раздел «Перед запуском») стоит строкой перед ними и в пять не входит. Бриф в чат не копируй. Ответы дают новую версию брифа и новую остановку. До шага 1 на стенде лежат `input.md`, `author-answers.md`, `brief.md`, `notes.md` и `status.json`.

Нельзя: выдумывать страну, цель, числа и плательщика; пересказывать условия автора, если пересказ меняет смысл, — такие места цитируй в «»; терять работы автора из-за лимита. Плательщика, которого не называют прямо ни вход, ни ответы автора, пиши «неизвестно» и спроси; «гипотеза» в разделе «Кто платит» не годится.

Шаблон брифа:

```markdown
# Бриф: <идея в 3–6 словах>

<ДД.ММ.ГГГГ>. Автор идеи: <кто>.
Дата решения: <ДД.ММ.ГГГГ — только для прошлых кейсов; иначе строки нет>

## Идея словами автора
<2–4 строки; слова автора в «»>

## Кто платит
- Платит: <кто> | неизвестно
- Решает о покупке: <кто> | неизвестно
- Пользуется: <кто>
- Держит деньги клиента: <кто> | неизвестно | не применимо
- Модель дохода и ставка: <как зарабатываем и сколько> | неизвестно
- Сейчас решают: <чем и за сколько> | неизвестно

## Цель автора
<сумма и дата словами автора> | Цели нет.

## Страна и покупатель
<страна или «неизвестно»>; <кто покупает>.
Лицензия или запрет: проверять — да | нет, <почему, одной строкой>.

## Работы клиента
1. I want to <…>[, чтобы <…>]. Уровень: Core. Из слов автора: «…».
2. …
Отложено: <работы, которые автор отложил> | нет.

## Пересчёт чисел автора
- «<число автора>» → <пересчёт>. Сходится | не сходится — вопрос <N>.

## Неизвестно
- <что неизвестно> — меняет <какой вывод>
- <что> — гипотеза: <какая>; меняет <какой вывод>

## Вопросы, от ответа на которые меняется вывод
1. <вопрос из пунктов 3 и 4; сначала плательщик и ставка и расхождения в числах автора, потом развилки, потом остальные — по силе>
```

Чисел для пересчёта нет — в разделе строка «Чисел для пересчёта нет».

## Шаг 1. Сбор

По одному агенту на каждую работу из брифа, все параллельно, в фоне, на самой сильной доступной модели. Каждому агенту — одно сообщение:

> Рабочая папка: `<абсолютный путь папки сессии>` — все пути ниже от неё, команды запускай из неё.
> SKILL=`<абсолютный путь папки скилла>`
> Прочитай `$SKILL/references/collect.md` и выполни его. RUN=`<абсолютный путь к папке прогона>`. Работа: `<строка работы из брифа дословно>`. Файл: `<короткое-имя-работы>.md`. Имя агента для снимков: `collect-<N>`.

Второй сборщик через Codex — когда человек просит или когда сайт закрыт для главного движка: в прогоне свопов reddit.com не открывался у Claude и открывался у Codex. Сообщение то же, файл `<короткое-имя-работы>-codex.md`, имя агента для снимков `collect-codex-<N>`; как запускать — раздел «Движки». Агент карты читает все `evidence/*.md`, так что оба сбора идут в карту вместе.

Дождись всех. У каждого файла первая строка после заголовка — «Счёт: …». Нет файла или агент упал — перезапусти этого агента один раз и запиши сбой в `notes.md`. Сразу запускай шаг 2: остановка — после него.

## Шаг 2. Сверка цитат

```bash
python3 $SKILL/tools/check_quotes.py --run RUN
```

Скрипт находит каждую цитату в `evidence/*.md`, `segments.md` и `card.md`, ищет её в снимке и зачёркивает те, которых в снимке нет. Итог — раздел «Сверка цитат» в `check.md`.

Сложи в строке итога «Зачёркнуты» и «Ошибок формата». Если сумма больше пятой части «Цитат» или «Цитат» — 0, на такой сбор опираться нельзя: запиши это в `notes.md`, скажи первой фразой на остановке и предложи перезапуск сбора.

Остановка после шагов 1 и 2: в 3–5 фразах — сколько эпизодов о работе в каждом файле сбора против нижней границы в пять, сколько цитат зачёркнуто из скольких, какие сайты не открылись. Строки «Счёт» и итог сверки в чат не копируй.

## Шаг 4. Проверка свежим агентом

Новый агент, который не видел разговора с автором:

> Рабочая папка: `<абсолютный путь папки сессии>` — все пути ниже от неё, команды запускай из неё.
> SKILL=`<абсолютный путь папки скилла>`
> Прочитай `$SKILL/references/review.md` и выполни его. RUN=`<абсолютный путь к папке прогона>`. Круг: `<N>`.

Он дописывает в `check.md` раздел «Проверка карты, круг N» и отвечает «Нарушений: K, из них спорно: S». Если K − S больше нуля, перезапусти шаг 3 новым агентом с добавкой:

> Исправь нарушения из раздела "Проверка карты, круг N" в check.md, кроме спорных.

Если человек уже решил что-то по спорным пунктам, допиши его слова дословно: «Решения человека по спорным: «…»». Потом снова шаг 4 со следующим номером круга. Спорные нарушения шаг 3 не перезапускают: их решает человек. Без решения человека — не больше двух кругов проверки. Перезапуск шага 3 по нарушениям проверки идёт без остановки: остановка — после последнего круга.

Остановка: в 3–5 фразах — число живых сегментов, строка «Нарушений: K, из них спорно: S» каждого круга и сколько нарушений осталось после второго круга. Спорные нарушения — дословно, если их не больше трёх, иначе числом. Дай пути к `segments.md`, `check.md` и `$SKILL/references/map-checklist.md` с подставленным путём; карту и список в чат не копируй. Спроси, принимает ли человек карту: как есть, с правкой, с досбором для сегмента или не принимает. Правка карты — шаг 3 новым агентом с его словами, без нового круга проверки. Не принимает — спроси, что дальше: досбор, новый бриф (шаг 0) или карточка по карте как есть с пометкой «карта не принята».

**Досбор для сегмента.** Проверка нашла у сегмента мало источников (пункт 4 в `map-checklist.md`), и человек просит искать дальше — запусти одного сборщика, у Claude или у Codex:

> Рабочая папка: `<абсолютный путь папки сессии>` — все пути ниже от неё, команды запускай из неё.

Сегмент: `<сегмент словами карты>`. Не бери сайт: `<домен, откуда больше половины доказательств сегмента>`. Файл: `<сегмент>-voices.md` (у Codex — `<сегмент>-voices-codex.md`). Имя агента для снимков: `voices-<N>`. Правка человека: «<слова дословно>».

## Шаг 5. Карточка решения

Один агент со свежим контекстом:

Карточка нужна и тогда, когда живых сегментов нет: автору всё равно нужен ответ и первая дешёвая проверка. Агент пишет `RUN/card.md` и сверяет его цитаты скриптом шага 2.

Остановка: ответ и проверка с порогом. «Да» — прогон закончен: все шаги в `status.json` — `done` или `skipped`, строка в `notes.md`, отправка на стенд. Последним сообщением дай ссылку на страницу прогона: прогон уже на стенде, пересылать его никому не надо. Стенд так и не ответил — скажи это и дай путь к папке прогона.

## Перезапуск одного шага

Шаг перезапускается на тех же входах: шаг 0 — на `input.md` и `author-answers.md`, шаг 1 — на `brief.md`, шаг 3 — на `brief.md`, `evidence/` и `check.md`, шаг 4 — на `segments.md`, `brief.md`, `evidence/` и `check.md`, шаг 5 — на `brief.md`, `author-answers.md`, `segments.md` и `check.md`. После перезапуска — строка в `notes.md`: какой шаг, что изменил и почему. Перезапуск шага 3 для сравнения — агенту добавь «перезапуск для сравнения»: он не читает прежние проверки карты. Новый прогон со шага N из старого — копируй только файлы шагов до N, а из `author-answers.md` — только вопросы и ответы до шага N. `.stand.json` не копируй: у нового прогона своя страница.

## Правила текста для всех шагов

- По-русски, короткими фразами, в действительном залоге.
- Бриф — до 50 строк, сбор — до 150 строк на работу, карта — до 100 строк, карточка — до 60 строк.
- В `brief.md`, `evidence/`, `segments.md` и `card.md` нет YAML, id правил и хэшей; английский — только в цитатах, в `I want to` и в названиях продуктов, компаний и сайтов.
- Номер снимка `src-NNN` и числа — по разделам «Строка цитаты» и «Числа» в `$SKILL/references/episode.md`.
- Гипотеза помечена словом «гипотеза». Неизвестное остаётся «неизвестно».
- Пустой раздел шаблона — строка «нет», если шаблон не велит иначе. Разделов сверх шаблона не добавляй.

## Движки

Каждое сообщение агенту начинается двумя строками: «Рабочая папка: <абсолютный путь папки сессии>» и «SKILL=<абсолютный путь папки скилла>». Агент стартует в папке сессии и папки скилла не знает: пути `$SKILL/…` он берёт из второй строки.

Claude Code: агенты — инструмент `Agent` с `run_in_background: true` и `model: "opus"`. Codex: `spawn_agent`. Главной сессии Codex нужны поиск и сеть: человек запускает её из папки сессии командой `bash $SKILL/tools/codex-run.sh`. Без поиска и сети падают `snap.py fetch` и `push_run.py`; тогда попроси человека перезапустить Codex этим скриптом. Если в движке нет субагентов, выполняй `$SKILL/references/collect.md`, `$SKILL/references/map.md`, `$SKILL/references/review.md` и `$SKILL/references/card.md` сам, по одному, начиная каждый шаг с чтения только его входов; `$SKILL` в них — твой путь к скиллу. Если карту строит и проверяет одна и та же сессия, запиши в `notes.md`: проверка шага 4 не независимая.

**Второй сборщик через Codex CLI.** Из Claude Code — командой Bash в фоне, из папки сессии:

```bash
codex --search exec -m gpt-6-sol -C "$PWD" --skip-git-repo-check -s workspace-write -c sandbox_workspace_write.network_access=true --json -o <scratch>/codex-<N>-last.md "<сообщение сборщика>" </dev/null > <scratch>/codex-<N>.jsonl 2>&1
```

`<scratch>` — временная папка вне `RUN`, у Claude Code — scratchpad сессии. `--search` — флаг самого `codex`, он стоит до `exec`; сеть в песочнице нужна для `snap.py fetch`. `--skip-git-repo-check` пускает `codex exec` в папку без git. Модель из конфига Codex аккаунт ChatGPT в CLI может не принять: проверь её одной строкой `codex exec --skip-git-repo-check -m <модель> "ответь ok" </dev/null` и возьми ту, что отвечает. К сообщению сборщика допиши:

> Файл другого сборщика не открывай, чужие снимки не трогай. Ничего не коммить и не пушь. Правила AGENTS.md и CLAUDE.md папки сессии к этой задаче не относятся.

Ответ сборщика — в `codex-<N>-last.md`, расход — в событии `turn.completed` в `codex-<N>.jsonl`.
