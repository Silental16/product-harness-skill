# Продуктовый харнесс · версия 2

Запрос → контекст о продукте → разбор запроса с человеком → ресёрч под проблему → группы клиентов → варианты → деньги и риски → первый шаг → ответ на гипотезу.

Харнесс отвечает до разработки на один из трёх вопросов: что строить, стоит ли строить X, сколько даст X. Фича уже выпущена — вопрос меняется сам: что она дала и что делать дальше. Пайплайн один на все запросы. Цепочка к прибыли — рынок с деньгами → сегмент и его работа → ценность → экономика → проверка на рынке (`nmt-key-theses.md` §4). На шаге 1 записываем, какие её звенья уже доказаны, и дальше ресёрч проверяет только недоказанные, каждое там, где о нём есть данные. Звено не доказано — ищем в открытых данных. Доказано, потому что клиенты уже платят, — опора на данные автора из входа и контекста, а с рынка берём, как ту же проблему снимают другие.

Ты — главная сессия. Шаг 1 ведёшь сам, в разговоре с человеком: просишь контекст о продукте, разбираешь запрос и сверяешь задачу. Шаг 2 делают сборщики, параллельно и в фоне. Шаги 3–7 пишет один агент синтеза в два файла: подробный и короткий. Каждый шаг читает файлы и пишет свой, поэтому любой шаг можно перезапустить отдельно.

Человек решает дважды: после разбора запроса и в конце. Середину он видит на странице прогона — так он не жмёт «да» вслепую на шагах, смысл которых ему не виден.

## Перед запуском

- Прочитай этот файл целиком.
- `SKILL` — абсолютный путь папки, где лежит этот `SKILL.md`. Пути `$SKILL/tools/…`, `$SKILL/references/…` и `$SKILL/ui/…` ниже — от неё. В командах подставляй путь целиком: переменной `SKILL` в shell нет.
- Прогон идёт в папке сессии — там, где её открыли; команды запускай из неё. Git прогону не нужен: ворктри, ветки, коммиты, пуши и PR не заводи. Запись прогона — стенд (раздел «Стенд»).
- `RUN` — папка `runs/<ГГГГ-ММ-ДД>-<идея>-<кто>/` в папке сессии. Создай её, положи вход автора как есть в `RUN/input.md`, заведи журнал по разделу «Журнал» и `status.json` по разделу «Страница прогона» (шаг `formula` — `running`) и сразу отправь прогон на стенд.
- Вход — путь к файлу или человек показал на файлы: прочитай их и положи их текст в `input.md` под его сообщением. Агенты не видят ничего, кроме папки прогона.
- Потом проверь `python3 -c "import yaml, bs4"`. Ошибка — попроси человека выполнить `python3 -m pip install --user pyyaml beautifulsoup4`: шаг 1 идёт и без них, а шаг 2 без них не запускай — не работают снимки и сверка цитат. Pip пишет `externally-managed-environment` — та же команда с `--break-system-packages`.
- `<идея>`, `<кто>`, имена файлов сборщиков — латиницей, строчными, через дефис: `2026-10-01-bali-tax-lena`, `players.md`. Эти имена уходят в ссылки страницы.
- Имени ведущего в сообщении нет — в имени папки пиши `anon`, в журнале «Ведёт: неизвестно», а имя спроси вместе с подтверждением задачи и впиши в «Ведёт:». Первым вопросом его не задавай: первый вопрос — о деле. Папку потом не переименовывай. Нет блока «Вход:» — в `input.md` идёт всё сообщение автора без слов о прогоне.
- Методология — только канон в `$SKILL/references/nmt/`, не по памяти. Для шага 1 прочитай `$SKILL/references/nmt/Next-Move-Theory-Canon/Next-Move-Theory/nmt-key-theses.md` §4 — цепочка к прибыли — и канон, который называет раздел «Шаг 1. Разбор запроса». Остальной канон читают агенты.
- Условия использования канона — `$SKILL/references/nmt/NOTICE.md`. Ключи, токены и пароли в файлы прогона не пиши: файлы уходят на стенд.
- Во время прогона не открывай другие прогоны, `cases/`, `lab/` и `pipeline/`: чужие выводы сдвинут твои.

## Папка прогона

```
RUN/
  input.md              вход автора как есть
  context.md            контекст о продукте: ответ человека и текст его файлов
  context/              файлы человека: документы, выгрузки, скриншоты
  author-answers.md     каждый вопрос человеку и его ответ, дословно
  formula.md            шаг 1: разбор запроса
  evidence/<тема>.md    шаг 2, файл на сборщика
  sources/              снимки: src-NNN.txt и src-NNN.yaml
  check.md              сверка цитат
  details.md            шаги 3–7, подробно, с цитатами
  card.md               шаги 3–7, коротко
  notes.md              журнал: кто ведёт, события, агенты, ответы, отклонения
  status.json           шаги и вопрос человеку для страницы прогона
  .stand.json           ключ записи прогона на стенде; пишет push_run.py
  ui.html               локальная страница прогона, когда стенд не отвечает
```

Перезапуск шага перезаписывает его файл, прежняя версия остаётся на стенде: он хранит каждую отправку. Снимки `sources/` и файлы `context/` на стенд не уходят и лежат только в папке прогона.

## Журнал

По журналу прогоны разных людей сравнивают и ищут, где прогон ошибся и сколько стоил. Поэтому пиши в него каждое событие из списка ниже — одной строкой, в одном формате, без пересказа файлов шагов.

`notes.md` начинается двумя строками:

```
# Заметки прогона: <идея>

Ведёт: <имя>. Движок: <Claude Code | Codex>, главная модель: <id модели>.
```

Главная модель — та, на которой идёт твоя сессия, а не догадка: она уходит в базу стенда, и по ней сравнивают прогоны. Claude Code берёт точный id модели из своего системного промпта (`claude-opus-5-5`), не псевдоним вроде `claude-opus-5[1m]`. Codex берёт значение `-m`, с которым его запустили, а без `-m` — `model` из `~/.codex/config.toml`.

Дальше — строка на событие. Формат строки: `ДД.ММ ЧЧ:ММ — шаг N — что случилось — модель — минуты — токены`. Это образец, а не строка журнала: в `notes.md` его не переписывай, пиши только настоящие события. Дата и время — с нулём впереди и по часам: `date '+%d.%m %H:%M'` даёт `01.10 09:05`. На глаз время не пиши — ни здесь, ни в `author-answers.md` и `status.json`. Модель: у агента — id модели (`claude-opus-5-5`), у скрипта — «скрипт», у человека — «человек». Минуты — целое число (`duration_ms` / 60000, с округлением), токены — только цифры, без запятых и слов; нет данных — «неизвестно». Строку в другом формате страница прогона не разберёт. Шаги 3–7 идут одним агентом — пиши их событиям «шаг 3».

События:
- запуск агента: какой агент, по какому файлу из `references/`, куда пишет; минуты и токены — `0 — 0`;
- конец агента: итог одной фразой, минуты и токены из отчёта агента о расходе. Claude Code даёт их в уведомлении о конце агента (`duration_ms`, `total_tokens`), Codex — в событии `turn.completed` своего JSON-вывода: токены = `input_tokens` + `output_tokens`. Не видно (так в сессии Codex без JSON-вывода) — «неизвестно»;
- ответ человека: `<имя>: «<слова дословно>»; <что решено>`, модель — «человек», `0 — 0`;
- каждый запуск сверки цитат: `сверка формулы: <строка «Цитаты формулы»>` или `сверка цитат: <строка «Цитат: …»>`, модель — «скрипт», `0 — 0`;
- перезапуск шага, сбой агента, ссылка стенда, ошибка отправки на стенд;
- отклонение от этого файла — что сделал иначе и почему; поломка скилла — какое правило или скрипт подвёл и как.

`author-answers.md` — каждый вопрос, который ты задаёшь человеку, и его ответ, дословно и со временем. Короткое «да» — тоже ответ.

```markdown
**Вопрос (ДД.ММ.ГГГГ ЧЧ:ММ, шаг N):** <вопрос, как ты его задал, с вариантами>
**Ответ (ЧЧ:ММ):** «<слова человека>»
```

## Как говорить с человеком

Человек не читал этот файл и не открывал файлы прогона. Пиши ему как коллеге: 2–5 простых фраз о смысле для его решения, а не о том, как работает скилл. Внутренние слова скилла в чат не неси: «нарушения», «круг проверки», «эпизоды», «сверка», «счёт», `src-NNN`, имена файлов, номера шагов, id полей. Вместо пути к файлу — ссылка на страницу прогона. Спорное, что можешь решить сам, решай сам и не неси человеку.

**Говори прямо.** Идея кажется сомнительной — скажи это первой фразой и назови причину: уже есть, не сходятся деньги, держится на одном слове автора. Не смягчай и не поддакивай; причину без источника помечай «гипотеза».

Между остановками человека ни о чём не спрашивай. Пишет в чат — ответь одной фразой и веди прогон дальше; просит поправить — правку учти на ближайшем шаге и запиши в журнал.

## Остановки

Остановок две: после шага 1 и после шага 7.

На каждой остановке:

1. Обнови `status.json`: итог шага в `summary`, шаг в `waiting`, вопрос в `question`. Отправь прогон на стенд (раздел «Стенд»).
2. Скажи итог по разделу «Как говорить с человеком», дай ссылку на страницу прогона и задай вопрос. Вопрос запиши в `author-answers.md`.
3. Жди. Следующий шаг начинай только после явного ответа.
4. Ответ запиши дословно в `author-answers.md`, строкой в `notes.md` и в `answers` в `status.json`; там же `question: null`, шаг — `done`, следующий — `running` со `started`. Отправь прогон на стенд.
5. Правку человека передавай агенту его словами, дословно: «Правка человека: «<слова>»». Не пересказывай: пересказ теряет смысл, а журнал должен показать, что человек просил. После правки — снова остановка.
6. «Да» с правкой («давай, только …») — учти правку, одной фразой скажи, что изменилось, и иди дальше.

## Стенд

Стенд — сайт команды, где лежит каждый прогон: его страница и общий список прогонов. Отправка на стенд:

```bash
python3 $SKILL/tools/push_run.py --run RUN
```

Скрипт шлёт `status.json`, файлы шагов, `input.md`, `author-answers.md` и журнал и печатает ссылку на страницу прогона. Первая отправка заводит прогон и кладёт ключ записи в `RUN/.stand.json`, следующие обновляют ту же страницу. `.stand.json` не копируй в другой прогон и не удаляй, кроме ошибки 403 ниже: без ключа стенд заведёт новую страницу, с чужим — откажет.

Когда отправлять:
- сразу после `input.md`, первых строк журнала и `status.json`, до проверки пакетов и первого вопроса: скрипту нужен только `python3`, а без `status.json` он прогон не отправит;
- после каждого вопроса шага 1 и каждого ответа на него — страница показывает вопрос, пока человек думает;
- на каждой остановке — после вопроса и после ответа человека (раздел «Остановки»);
- при запуске шага без остановки перед ним (шаги 3–7 после сбора, перезапуск шага), когда шаг уже `running` со `started`;
- после конца каждого агента, когда его строка уже в `notes.md`.

Ссылку даёт первая удачная отправка. Сразу дай её человеку отдельной строкой — в начале прогона это первая строка в чат — и запиши в `notes.md`: `ДД.ММ ЧЧ:ММ — шаг 1 — стенд: <ссылка> — скрипт — 0 — 0`.

Ошибка — одна строка `стенд: <причина>` и код 1. Запиши её событием в `notes.md`, модель — «скрипт», и иди дальше: прогон стенда не ждёт, следующая отправка пробует снова. Ошибка 403 («чужой прогон») сама не пройдёт: удали `RUN/.stand.json` и отправь снова — стенд заведёт новую страницу. Новую ссылку дай человеку и запиши в `notes.md`. Пока стенд не отвечает, на остановке давай вместо ссылки путь к локальной странице (раздел «Страница прогона»). Код 0 и строка `стенд: не влезли …` — отправка прошла без этих файлов: запиши строку в `notes.md`.

Человек сказал не слать прогон на стенд — `push_run.py` не запускай, на остановках давай путь к локальному `ui.html`.

Страница прогона открывается по ссылке без пароля — дай ссылку человеку сразу. Список всех прогонов спрашивает общий пароль команды; его даёт людям Андрей, ты его не знаешь и не спрашиваешь. В Codex отправке нужна сеть — раздел «Движки».

## Страница прогона

Человек следит за прогоном на странице стенда: шаги и их итоги, тексты файлов, журнал из `notes.md` и открытый вопрос. Дизайн один на все прогоны — `$SKILL/ui/page.html`, данные шлёт `push_run.py`. Отвечает человек в чате.

`RUN/status.json` ведёшь ты. Образец — `$SKILL/references/status-example.json`: прогон на последней остановке. Шаги, их файлы и разделы:

- `formula` 1 «Разбор запроса» — `formula.md`, `context.md`, `input.md`; раздел «Коротко»;
- `market` 2 «Ресёрч под проблему» — `card.md`, `details.md`, `check.md` и файлы сборщиков; разделы «Проблема в данных», «Что уже есть у нас», «Конкуренты»;
- `segments` 3 «Кого касается» — `card.md`, `details.md`; раздел «Кого касается»;
- `solutions` 4 «Варианты» — `card.md`, `details.md`; раздел «Варианты»;
- `money` 5 «Деньги и риски» — `card.md`, `details.md`; раздел «Деньги и риски»;
- `test` 6 «Первый шаг» — `card.md`, `details.md`; раздел «Первый шаг»;
- `card` 7 «Ответ на гипотезу» — `card.md`, `details.md`; разделы «Ответ на гипотезу», «Не знаем».

Раздел шага — поле `section`: имя раздела или список имён. Страница показывает итогом шага текст этих разделов из его файлов, когда шаг `done` или `waiting`, — копировать текст в `status.json` не нужно. Без `steps` скрипт подставит все семь шагов сам со статусом `next`, но без файлов сборщиков: их впиши сам. Файл не в списке шага на стенд не уходит.

Скелет файла:

```json
{"run": "<папка прогона>", "title": "<запрос в 3–6 словах>", "updated": "ДД.ММ.ГГГГ ЧЧ:ММ",
 "steps": [{"id": "formula", "n": 1, "title": "Разбор запроса", "status": "running",
            "files": ["formula.md", "context.md", "input.md"], "section": "Коротко",
            "summary": "…", "started": "ЧЧ:ММ", "finished": "ЧЧ:ММ"}, "…ещё шесть шагов…"],
 "question": {"id": "q-1", "step": "formula", "text": "…", "items": ["…", "не знаю"], "asked": "ЧЧ:ММ"},
 "answers": [{"id": "q-1", "step": "formula", "text": "…", "answer": "…", "at": "ЧЧ:ММ"}]}
```

- `status` шага — `done`, `running`, `waiting` (ждёт человека), `next` или `skipped`. `summary` — первые 1–3 фразы итога, который ты даёшь в чате; у шагов 3–6 его можно не писать — страница покажет их разделы.
- `question` — `null` или вопрос; `question.step` — id шага, к которому он относится. `items` — строки под `text` на странице стенда. В просьбе о контексте это её пункты, на остановке 1 — вопросы автору, строка на вопрос с вариантами. В остальных вопросах — варианты ответа, строка на вариант, «не знаю» последним. `id` вопросов идут подряд: `q-1`, `q-2`, … Без `run` черновики ответов разных прогонов смешаются, без нового `id` черновик прошлого вопроса всплывёт в следующем.
- Стенд не отвечает — собери страницу локально и дай человеку путь `file://<абсолютный путь RUN>/ui.html`. В браузере она только показывает прогон: человек отвечает в чате.
  ```bash
  python3 $SKILL/tools/render_ui.py --run RUN
  ```

## Шаг 1. Разбор запроса

Ведёшь сам, в разговоре, без агента и без поиска в сети. Сначала просишь у человека контекст о продукте, потом разбираешь запрос по канону и показываешь человеку задачу, как её понял харнесс. От разбора зависит, что будет искать ресёрч, поэтому ошибка здесь обходится дороже всего.

**Контекст о продукте.** Первое сообщение человеку — ссылка на страницу прогона и под ней одна просьба:

> Чтобы ответ стоял на твоих цифрах, а не на догадках, дай как можно больше контекста о продукте — одним сообщением, в любом виде.
> 1. Что за продукт и для кого: кто им пользуется, на каком шаге работает идея. Если нет — напиши «нет».
> 2. Кто платит и сколько: цена, за что берут деньги, выручка в месяц. Если нет — напиши «нет».
> 3. Цифры шага, который меняет идея: сколько людей проходит его в месяц, конверсия, где и сколько уходят. Если нет — напиши «нет».
> 4. Выручка и маржа на одного клиента или одну сделку. Если нет — напиши «нет».
> 5. Что уже пробовали и чем кончилось. Если нет — напиши «нет».
> 6. Документы, ссылки, выгрузки, скриншоты: приложи файлы или дай пути к ним. Если нет — напиши «нет».
>
> Всё это попадёт на страницу прогона на стенде команды харнесса. Данные нельзя выносить — напиши «без стенда».

Пункт, на который вход уже отвечает целиком, из просьбы убери. Больше семи пунктов не добавляй: это просьба, а не анкета. Просьба — вопрос `q-1`: строка в `author-answers.md`, `question` в `status.json` с пунктами в `items`, шаг 1 — `waiting`, отправка на стенд. Ответ — дословно в `author-answers.md` и в `answers`, строка в `notes.md`, шаг 1 — снова `running`. «Без стенда» — дальше `push_run.py` не запускай (раздел «Стенд»).

Потом запиши `RUN/context.md`. Файлы человека скопируй в `RUN/context/`: агенты видят только папку прогона. Текст файла клади в `context.md` под его именем. Скриншот, скан или выгрузку длиннее 300 строк пиши своими словами: что в файле, какие числа и за какой период. Ссылку, которую дал человек, открой: открылась — её текст под её адресом, нет — строка «не открылась».

```markdown
# Контекст о продукте

<ДД.ММ.ГГГГ ЧЧ:ММ>. Дал <имя>. | Контекста нет: «<ответ человека>». | Человека нет: не запрашивали.

## Ответ человека
<его сообщение как есть>

## <имя файла или адрес ссылки>
<текст как есть | что в нём, своими словами>
```

`context.md` — данные автора. На них стоят «Работа клиента и где рвётся», группы клиентов и деньги. В «» в формуле идут только слова человека из входа и ответов; числа и факты из его файлов пиши своими словами, с пометкой «из контекста».

Человек ничего не дал — прогон идёт. Тогда в пункте «Каких данных нет» прямо назови, каких чисел не хватило и при каком их значении меняется решение: «поток через шаг: меньше 2 000 человек в месяц — доработка не окупит неделю работы». Синтез перенесёт это в «Не знаем» отчёта.

**Разбор по канону.** Прочитай `context.md` и канон в `$SKILL/references/nmt/Next-Move-Theory-Canon/`:
- `Algorithms/the-algorithm.md`, шаги 1–2 — «зачем?» вверх до цели и что уже решали;
- `Advanced-Jobs-To-Be-Done/job-structure.md` §7 — работа клиента `I want to …`;
- `Advanced-Jobs-To-Be-Done/job-types-and-properties.md` §8 — ложная работа: у нового продукта проверь, делал ли клиент эту работу раньше;
- `Advanced-Jobs-To-Be-Done/segmentation.md` §7 — причинный признак: от какого свойства клиента зависит решение.

Сначала назови вид запроса: готовое решение («сделать X»), проблема, цель, новый рынок или продукт. Любой вид сведи к одной гипотезе.

**Пересчитай числа автора** — тем же проходом, во входе и в контексте: суммы, произведения, периоды, кого считает каждое число. `14 млн × 1%` — это 140 тыс., а не 14 тыс. `5 + 14 + 6 = 25` не доказывает, что группы не пересекаются. Числа расходятся — сначала проверь, не о разных ли группах, периодах или слоях они говорят: люди и заходы, оборот и выручка. Объяснение годится, только если его дал вход или человек; не объяснилось — это вопрос. Числа во входе и в контексте не правь.

**Запиши `RUN/formula.md`**, не длиннее 60 строк:

```markdown
# Разбор запроса: <запрос в 3–6 словах>

<ДД.ММ.ГГГГ>. Подтвердил <имя>: «<его ответ>». | Ещё не подтверждён. | Человека нет, разбор из входа.
Дата решения: <ДД.ММ.ГГГГ — только для прошлого кейса; иначе строки нет>

## Коротко
- **Что пришло.** <вид запроса; суть словами автора в «»; что автор обещает>
- **Статус.** <не начато | в работе | выпущено, дата; что из этого уже работает>
- **Цель уровнем выше.** <зачем? — вверх до денег; улучшение работающего или новое>
- **Что уже было.** <что пробовали и выпускали, чем кончилось>
- **Работа клиента и где рвётся.** <I want to …; звено, где рвётся цепочка, и насколько>
- **Возможные причины.** <2–5 кандидатов: причина — барьер | страх | мало ценности — подтверждена данными | не проверена>
- **Механики.** <какую применяет решение автора; 1–3 других на тот же разрыв>
- **Гипотеза.** Если <решение или механика> для <кого> в <работе>, то <метрика> изменится на <N> и даст <деньги в месяц>.
- **Каких данных нет.** <число — при каком его значении меняется решение | всё нужное есть>
- **Что решаем.** <какое решение человек примет по ответу>

## Вопросы автору
1. <вопрос> — <вариант> | <вариант> | не знаю
<человека нет — последней строкой «В этом прогоне не задавали»>

## Запрос словами автора
<1–3 строки; слова автора в «»>

## Формула
- **Что хочу понять:** …
- **Зачем:** …
- **Цель:** …
- **Продукт:** …
- **Решение автора:** …
- **Для кого:** …
- **Что уже доказано:** …
- **Боль:** …
- **Рынки:** …
- **Рамки:** …

## Пересчёт чисел автора
- «<число автора>» → <пересчёт>. Сходится | не сходится — <что это меняет>.
```

Как заполнять «Коротко»:
- **Статус** — из входа и контекста. Выпущено — вопрос меняется: что это дало и что дальше; так же меняй «Что хочу понять». Прошлый кейс — статус на дату решения: выпуск позже неё не бери и вопрос не меняй.
- **Цель уровнем выше** — «зачем?» 3–5 раз, пока не дойдёшь до денег.
- **Работа клиента и где рвётся** — звено и число берёшь из `context.md`; нет числа — «неизвестно», и это строка в «Каких данных нет».
- **Возможные причины** — 2–5 кандидатов. Вид у каждого: барьер (не может пройти), страх (может, но боится), мало ценности (прошёл, а результат хуже ожидания). Подтверждённую данными так и пометь.
- **Механики** — какую механику применяет решение автора и 1–3 других на тот же разрыв. Список механик и правило «вид причины → механика» — шаг 4 в `$SKILL/references/card.md`. Названия механик пиши без «»: во входе их нет, и `--formula` их зачеркнёт.

Поля раздела «Формула» пиши словами человека: их читают сборщики шага 2, а разбор по канону идёт в «Коротко» и запрос автора не подменяет.
- **Что хочу понять:** «что строить» | «стоит ли строить X» | «сколько даст X» | «что дал X и что дальше» — X уже выпущен.
- **Зачем:** какое решение человек примет по ответу.
- **Цель:** деньги к дате | метрика с базой сравнения («+30% оборота к контрольной группе за 6 месяцев») | цели нет.
- **Продукт:** нет | есть, платят <кто> за <что>. Возьми из контекста; не спрашивай то, на что он ответил.
- **Решение автора:** <что предлагает> | нет.
- **Для кого:** покупатель | продавец, мерчант или партнёр | оба. У двустороннего продукта две стороны — здесь решаем, с какой начинаем.
- **Что уже доказано:** звенья цепочки к прибыли, которые уже стоят на фактах из входа, контекста или ответов человека. У каждого — откуда это известно.
- **Боль:** что, по словам автора, у клиента не так, с меткой «подтверждено данными» или «только со слов автора».
- **Рынки:** 1–3 кандидата. Продавец и покупатель живут в разных странах — указываем обе: законы о продаже и о покупке разные.
- **Рамки:** что нельзя и что обязательно.

**Вопросы автору** — до пяти, одним сообщением, у каждого 2–4 варианта и «не знаю»: верна ли задача, числа, которые не сходятся, порог успеха. На что ответили вход и контекст, не спрашивай. Спрашивай только то, что знает один человек: цель, решение, рамки, свои факты и цифры. Кто платит на рынке, сколько там денег и кто конкуренты — не спрашивай: это ищет ресёрч. Вопрос годится, если ответы «А» и «Б» поведут ресёрч по-разному; иначе запиши допущение в формулу и не спрашивай. «Не знаю» — законный ответ: поле становится «неизвестно» или допущением с пометкой.

Чисел нет — в разделе пересчёта строка «Чисел для пересчёта нет». Потом сверь цитаты формулы: `python3 $SKILL/tools/check_quotes.py --run RUN --formula`. Скрипт ищет каждую «цитату» в `input.md` и в ответах человека и зачёркивает те, которых там нет. Поправь зачёркнутое и неточное — слова автора дословно в «», свои слова без кавычек — и запусти снова, пока в строке «Цитаты формулы» не станет «Неточно: 0. Зачёркнуты: 0».

**Остановка 1.** В чат — пункты «Коротко», вопросы автору одним сообщением и ссылка на страницу прогона. Фича уже выпущена или вход и контекст показывают, что то же уже сделано, — скажи это первой фразой: это переворачивает запрос. Спроси: «Задача поставлена верно? Если да — запускаю ресёрч». В `status.json` этот вопрос — `question.text`, вопросы автору — `items`, строка на вопрос с вариантами. Нет имени — тем же сообщением спроси, как записать его в журнал. Правка — новая версия `formula.md` и снова остановка. После «да» учти ответы в «Коротко» и «Формуле», впиши во вторую строку, кто и какими словами подтвердил, и снова сверь цитаты формулы. Ресёрч начинай только после «да».

**Человека нет.** Прогон прошлого кейса или проверка скилла, и отвечать некому: контекст не запрашивай — в `context.md` строка «Человека нет: не запрашивали», данные только из входа. Разбор собери из входа, где ответа нет — «не знаю» плюс допущение, с которым идёшь дальше. Вопросы остаются в «Вопросы автору» с пометкой «в этом прогоне не задавали», у каждого — варианты ответа и что от ответа изменится. Остановок нет: после разбора — сразу шаг 2, после шага 7 прогон закрывается без вопроса.

## Шаг 2. Ресёрч под проблему

Ресёрч ищет не решение автора, а как снять разрыв из «Работа клиента и где рвётся». Сборщики, все параллельно, в фоне, на модели главной сессии (раздел «Движки»):
- тема «конкуренты: как решают ту же проблему», файл `players.md`. Прямые и косвенные конкуренты, те, кто закрывает всю задачу клиента, и крупный игрок, который включит то же одним релизом;
- только для нового рынка или нового продукта — по сборщику на каждый рынок из формулы, тема «рынок: <рынок>», файл `<рынок>.md`.

Доработка работающего продукта: рынок доказан, хватит `players.md`. Свои данные — поток через шаг, где уходят, группы клиентов — дал человек в `context.md`, сборщики их не ищут.

Каждому сборщику — одно сообщение:

> Рабочая папка: `<абсолютный путь папки сессии>` — все пути ниже от неё, команды запускай из неё.
> SKILL=`<абсолютный путь папки скилла>`
> Прочитай `$SKILL/references/collect.md` и выполни его. RUN=`<абсолютный путь к папке прогона>`. Тема: `<тема>`. Файл: `<имя>.md`. Имя агента для снимков: `collect-<N>`.

Второй сборщик через Codex — когда человек просит или когда сайт закрыт для главного движка: в одном прогоне reddit.com не открывался у Claude и открывался у Codex. Сообщение то же, файл `<имя>-codex.md`, имя агента для снимков `collect-codex-<N>`; как запускать — раздел «Движки».

Дождись всех. Нет файла или агент упал — перезапусти этого агента один раз и запиши сбой в `notes.md`. Потом сверь цитаты:

```bash
python3 $SKILL/tools/check_quotes.py --run RUN
```

Скрипт находит каждую цитату в `evidence/*.md`, `details.md` и `card.md`, ищет её в снимке и зачёркивает те, которых там нет. Итог — раздел «Сверка цитат» в `check.md`. Сложи в строке итога «Зачёркнуты» и «Ошибок формата». Сумма больше пятой части «Цитат» или «Цитат» — 0 — на такой сбор опираться нельзя: запиши это в `notes.md`, перезапусти сборщиков с худшими файлами один раз и скажи об этом человеку одной фразой.

Шаг 2 — `done`, в `summary` — что принесли сборщики, простыми словами. Остановки нет: сразу шаги 3–7. Разделы шага 2 на странице появятся, когда агент синтеза запишет `card.md`.

## Шаги 3–7. Кого касается, варианты, деньги и риски, первый шаг, ответ на гипотезу

Один агент со свежим контекстом. Он читает только `formula.md`, `context.md` и `evidence/`, в сеть не ходит и пишет два файла: сначала `details.md` — подробно, с цитатами и расчётами, потом по нему `card.md` — коротко, для менеджера:

> Рабочая папка: `<абсолютный путь папки сессии>` — все пути ниже от неё, команды запускай из неё.
> SKILL=`<абсолютный путь папки скилла>`
> Прочитай `$SKILL/references/card.md` и выполни его. RUN=`<абсолютный путь к папке прогона>`.

На время работы агента шаги 3–7 — `running` с одним `started`. Агент сам сверяет цитаты и правит файлы по сверке. Когда он закончил, проверь, что в `details.md` и `card.md` есть все разделы их шаблонов из `references/card.md` и что в разделе «Сверка цитат» в `check.md` нет строк про `details.md` и `card.md`. Шаги 3–6 — `done` с `finished`, шаг 7 — `waiting`.

**Остановка 2.** В чат — до шести строк: «Ответ», варианты «в работу первым», «Первый шаг» и ссылка на страницу прогона. Спроси: «Закрываем или копаем глубже по одному варианту?»
- «Да», «закрываем» — прогон закончен: все шаги в `status.json` — `done` или `skipped`, строка в `notes.md`, отправка на стенд. Последним сообщением дай ссылку на страницу прогона: прогон уже на стенде, пересылать его никому не надо. Стенд так и не ответил — скажи это и дай путь к папке прогона.
- Правка отчёта («это не так», «посчитай с другой ценой») — новый агент шагов 3–7 с тем же сообщением и добавкой «Правка человека: «<слова дословно>»». Потом снова остановка.
- «Копай глубже по …» — один сборщик с темой словами человека, файл по теме. На время досбора шаг 2 — `running`. Потом сверка цитат, агент шагов 3–7 с добавкой «Учти новый файл `evidence/<файл>`. Правка человека: «<слова дословно>»» и снова остановка.

## Перезапуск одного шага

Шаг перезапускается на тех же входах: шаг 1 — на `input.md`, `context.md` и `author-answers.md`, шаг 2 — на `formula.md` и `input.md`, шаги 3–7 — на `formula.md`, `context.md`, `evidence/` и `check.md` и пишут оба файла, `details.md` и `card.md`. После перезапуска — строка в `notes.md`: какой шаг, что изменил и почему. Перезапуск шагов 3–7 без правки пишет `details.md` и `card.md` заново: прежние агент не читает, а прежняя версия остаётся на стенде. Новый прогон со шага N из старого — копируй только файлы шагов до N, с `context.md` и `context/`, а из `author-answers.md` — только вопросы и ответы до шага N. `.stand.json` не копируй: у нового прогона своя страница.

## Правила текста

- По-русски, короткими фразами, в действительном залоге.
- `formula.md` — до 60 строк, сбор — до 150 строк на файл, `details.md` — до 160 строк и до 25 строк цитат, `card.md` — до 80 строк, без строк цитат.
- В `formula.md`, `evidence/`, `details.md` и `card.md` нет YAML, id правил и хэшей; английский — только в цитатах, в `I want to` и в названиях продуктов, компаний и сайтов.
- Номер снимка `src-NNN` и числа — по разделам «Строка цитаты» и «Числа» в `$SKILL/references/quotes.md`.
- Гипотеза помечена словом «гипотеза», оценка — словом «оценка» с расчётом. Неизвестное остаётся «неизвестно».
- Не выдумывай компании, цены и числа. Не нашлось — «не знаем».
- Пустой раздел шаблона — строка «нет», если шаблон не велит иначе. Разделов сверх шаблона не добавляй.

## Движки

Каждое сообщение агенту начинается двумя строками: «Рабочая папка: <абсолютный путь папки сессии>» и «SKILL=<абсолютный путь папки скилла>». Агент стартует в папке сессии и папки скилла не знает: пути `$SKILL/…` он берёт из второй строки.

Агенты идут на той модели, на которой человек запустил сессию: какую он выбрал, на той и гоняется прогон. Модель агентам не задавай и не подменяй — ни сильнее, ни дешевле. Прогоны сравнивают по главной модели из `notes.md`, и агент на другой модели ломает это сравнение и меняет цену прогона.

Claude Code: агенты — инструмент `Agent` с `run_in_background: true`, без параметра `model`: так агент берёт модель главной сессии. Codex: `spawn_agent` без `model` и `thinking`, по той же причине. Главной сессии Codex нужны поиск и сеть: человек запускает её из папки сессии командой `bash $SKILL/tools/codex-run.sh`. Без поиска и сети падают `snap.py fetch` и `push_run.py`; тогда попроси человека перезапустить Codex этим скриптом. Если в движке нет субагентов, выполняй `$SKILL/references/collect.md` по каждой теме и потом `$SKILL/references/card.md` сам, по одному, начиная каждый с чтения только его входов; `$SKILL` в них — твой путь к скиллу. Тогда запиши в `notes.md`: синтез не независим от разговора с человеком.

**Второй сборщик через Codex CLI.** Из Claude Code — командой Bash в фоне, из папки сессии:

```bash
codex --search exec -C "$PWD" --skip-git-repo-check -s workspace-write -c sandbox_workspace_write.network_access=true --json -o <scratch>/codex-<N>-last.md "<сообщение сборщика>" </dev/null > <scratch>/codex-<N>.jsonl 2>&1
```

`<scratch>` — временная папка вне `RUN`, у Claude Code — scratchpad сессии. `--search` — флаг самого `codex`, он стоит до `exec`; сеть в песочнице нужна для `snap.py fetch`. `--skip-git-repo-check` пускает `codex exec` в папку без git. Без `-m` Codex берёт модель из своего конфига — ту, что выбрал человек. Аккаунт ChatGPT в CLI может её не принять: проверь одной строкой `codex exec --skip-git-repo-check "ответь ok" </dev/null`. Не отвечает — спроси человека, какую модель Codex взять, допиши её в команду как `-m <модель>` и запиши в `notes.md`. К сообщению сборщика допиши:

> Файл другого сборщика не открывай, чужие снимки не трогай. Ничего не коммить и не пушь. Правила AGENTS.md и CLAUDE.md папки сессии к этой задаче не относятся.

Ответ сборщика — в `codex-<N>-last.md`, расход — в событии `turn.completed` в `codex-<N>.jsonl`.
