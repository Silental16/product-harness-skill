# Продуктовый харнесс · версия 2

Запрос → формула запроса с человеком → кто уже это делает и рынок → сегменты → решения → деньги и отсев → проверка → карта возможностей.

Харнесс отвечает до разработки на один из трёх вопросов: что строить, стоит ли строить X, сколько даст X. Пайплайн один на все запросы. Цепочка к прибыли — рынок с деньгами → сегмент и его работа → ценность → экономика → проверка на рынке (`nmt-key-theses.md` §4). На шаге 1 записываем, какие её звенья уже доказаны, и дальше ресерч проверяет только недоказанные, каждое там, где о нём есть данные. Звено не доказано — ищем в открытых данных. Доказано, потому что клиенты уже платят, — опора на свои данные из входа, а с рынка берём аналоги и бенчмарки.

Ты — главная сессия. Шаг 1 ведёшь сам, в разговоре с человеком. Шаг 2 делают сборщики, параллельно и в фоне. Шаги 3–7 пишет один агент синтеза в один файл. Каждый шаг читает файлы и пишет свой, поэтому любой шаг можно перезапустить отдельно.

Человек решает дважды: после формулы и в конце. Середину он видит на странице прогона — так он не жмёт «да» вслепую на шагах, смысл которых ему не виден.

## Перед запуском

- Прочитай этот файл целиком.
- `SKILL` — абсолютный путь папки, где лежит этот `SKILL.md`. Пути `$SKILL/tools/…`, `$SKILL/references/…` и `$SKILL/ui/…` ниже — от неё. В командах подставляй путь целиком: переменной `SKILL` в shell нет.
- Прогон идёт в папке сессии — там, где её открыли; команды запускай из неё. Git прогону не нужен: ворктри, ветки, коммиты, пуши и PR не заводи. Запись прогона — стенд (раздел «Стенд»).
- `RUN` — папка `runs/<ГГГГ-ММ-ДД>-<идея>-<кто>/` в папке сессии. Создай её, положи вход автора как есть в `RUN/input.md`, заведи журнал по разделу «Журнал» и `status.json` по разделу «Страница прогона» (шаг `formula` — `running`) и сразу отправь прогон на стенд.
- Вход — путь к файлу или человек показал на файлы: прочитай их и положи их текст в `input.md` под его сообщением. Агенты не видят ничего, кроме папки прогона.
- Потом проверь `python3 -c "import yaml, bs4"`. Ошибка — попроси человека выполнить `python3 -m pip install --user pyyaml beautifulsoup4`: шаг 1 идёт и без них, а шаг 2 без них не запускай — не работают снимки и сверка цитат. Pip пишет `externally-managed-environment` — та же команда с `--break-system-packages`.
- `<идея>`, `<кто>`, имена файлов сборщиков — латиницей, строчными, через дефис: `2026-10-01-bali-tax-lena`, `players.md`. Эти имена уходят в ссылки страницы.
- Имени ведущего в сообщении нет — в имени папки пиши `anon`, в журнале «Ведёт: неизвестно», а имя спроси вместе с подтверждением формулы и впиши в «Ведёт:». Первым вопросом его не задавай: первый вопрос — о деле. Папку потом не переименовывай. Нет блока «Вход:» — в `input.md` идёт всё сообщение автора без слов о прогоне.
- Методология — только канон в `$SKILL/references/nmt/`, не по памяти. Для шага 1 прочитай `$SKILL/references/nmt/Next-Move-Theory-Canon/Next-Move-Theory/nmt-key-theses.md` §4 — цепочка к прибыли. Остальной канон читают агенты.
- Условия использования канона — `$SKILL/references/nmt/NOTICE.md`. Ключи, токены и пароли в файлы прогона не пиши: файлы уходят на стенд.
- Во время прогона не открывай другие прогоны, `cases/`, `lab/` и `pipeline/`: чужие выводы сдвинут твои.

## Папка прогона

```
RUN/
  input.md              вход автора как есть
  author-answers.md     каждый вопрос человеку и его ответ, дословно
  formula.md            шаг 1
  evidence/<тема>.md    шаг 2, файл на сборщика
  sources/              снимки: src-NNN.txt и src-NNN.yaml
  check.md              сверка цитат
  card.md               шаги 3–7
  notes.md              журнал: кто ведёт, события, агенты, ответы, отклонения
  status.json           шаги и вопрос человеку для страницы прогона
  .stand.json           ключ записи прогона на стенде; пишет push_run.py
  ui.html               локальная страница прогона, когда стенд не отвечает
```

Перезапуск шага перезаписывает его файл, прежняя версия остаётся на стенде: он хранит каждую отправку. Снимки `sources/` на стенд не уходят и лежат только в папке прогона.

## Журнал

По журналу прогоны разных людей сравнивают и ищут, где прогон ошибся и сколько стоил. Поэтому пиши в него каждое событие из списка ниже — одной строкой, в одном формате, без пересказа файлов шагов.

`notes.md` начинается двумя строками:

```
# Заметки прогона: <идея>

Ведёт: <имя>. Движок: <Claude Code | Codex>, главная модель: <id модели>.
```

Главная модель — та, на которой идёт твоя сессия, а не догадка: она уходит в базу стенда, и по ней сравнивают прогоны. Claude Code берёт точный id модели из своего системного промпта (`claude-opus-5-5`), не псевдоним вроде `claude-opus-5[1m]`. Codex берёт значение `-m`, с которым его запустили, а без `-m` — `model` из `~/.codex/config.toml`.

Дальше — строка на событие. Формат строки: `ДД.ММ ЧЧ:ММ — шаг N — что случилось — модель — минуты — токены`. Это образец, а не строка журнала: в `notes.md` его не переписывай, пиши только настоящие события. Дата и время — с нулём впереди и по часам: `date '+%d.%m %H:%M'` даёт `01.10 09:05`. На глаз время не пиши — ни здесь, ни в `author-answers.md` и `status.json`. Модель: у агента — id модели (`claude-opus-5-5`), у скрипта — «скрипт», у человека — «человек». Минуты — целое число (`duration_ms` / 60000, с округлением), токены — только цифры, без запятых и слов; нет данных — «неизвестно». Строку в другом формате страница прогона не разберёт. Шаги 3–7 идут одним агентом — пиши их событиям «шаг 3».

События:
- запуск агента: какой агент, по какому файлу из `references/`, куда пишет; минуты и токены — `0 — 0`;
- конец агента: итог одной фразой, минуты и токены из отчёта агента о расходе. Claude Code даёт их в уведомлении о конце агента (`duration_ms`, `total_tokens`), Codex — в событии `turn.completed` своего JSON-вывода: токены = `input_tokens` + `output_tokens`. Не видно (так в сессии Codex без JSON-вывода) — «неизвестно»;
- ответ человека: `<имя>: «<слова дословно>»; <что решено>`, модель — «человек», `0 — 0`;
- каждый запуск сверки цитат: `сверка формулы: <строка «Цитаты формулы»>` или `сверка цитат: <строка «Цитат: …»>`, модель — «скрипт», `0 — 0`;
- перезапуск шага, сбой агента, ссылка стенда, ошибка отправки на стенд;
- отклонение от этого файла — что сделал иначе и почему; поломка скилла — какое правило или скрипт подвёл и как.

`author-answers.md` — каждый вопрос, который ты задаёшь человеку, и его ответ, дословно и со временем. Короткое «да» — тоже ответ.

```markdown
**Вопрос (ДД.ММ.ГГГГ ЧЧ:ММ, шаг N):** <вопрос, как ты его задал, с вариантами>
**Ответ (ЧЧ:ММ):** «<слова человека>»
```

## Как говорить с человеком

Человек не читал этот файл и не открывал файлы прогона. Пиши ему как коллеге: 2–5 простых фраз о смысле для его решения, а не о том, как работает скилл. Внутренние слова скилла в чат не неси: «нарушения», «круг проверки», «эпизоды», «сверка», «счёт», `src-NNN`, имена файлов, номера шагов, id полей. Вместо пути к файлу — ссылка на страницу прогона. Спорное, что можешь решить сам, решай сам и не неси человеку.

Между остановками человека ни о чём не спрашивай. Пишет в чат — ответь одной фразой и веди прогон дальше; просит поправить — правку учти на ближайшем шаге и запиши в журнал.

## Остановки

Остановок две: после шага 1 и после шага 7.

На каждой остановке:

1. Обнови `status.json`: итог шага в `summary`, шаг в `waiting`, вопрос в `question`. Отправь прогон на стенд (раздел «Стенд»).
2. Скажи итог по разделу «Как говорить с человеком», дай ссылку на страницу прогона и задай вопрос. Вопрос запиши в `author-answers.md`.
3. Жди. Следующий шаг начинай только после явного ответа.
4. Ответ запиши дословно в `author-answers.md`, строкой в `notes.md` и в `answers` в `status.json`; там же `question: null`, шаг — `done`, следующий — `running` со `started`. Отправь прогон на стенд.
5. Правку человека передавай агенту его словами, дословно: «Правка человека: «<слова>»». Не пересказывай: пересказ теряет смысл, а журнал должен показать, что человек просил. После правки — снова остановка.
6. «Да» с правкой («давай, только …») — учти правку, одной фразой скажи, что изменилось, и иди дальше.

## Стенд

Стенд — сайт команды, где лежит каждый прогон: его страница и общий список прогонов. Отправка на стенд:

```bash
python3 $SKILL/tools/push_run.py --run RUN
```

Скрипт шлёт `status.json`, файлы шагов, `input.md`, `author-answers.md` и журнал и печатает ссылку на страницу прогона. Первая отправка заводит прогон и кладёт ключ записи в `RUN/.stand.json`, следующие обновляют ту же страницу. `.stand.json` не копируй в другой прогон и не удаляй, кроме ошибки 403 ниже: без ключа стенд заведёт новую страницу, с чужим — откажет.

Когда отправлять:
- сразу после `input.md`, первых строк журнала и `status.json`, до проверки пакетов и первого вопроса: скрипту нужен только `python3`, а без `status.json` он прогон не отправит;
- после каждого вопроса шага 1 и каждого ответа на него — страница показывает вопрос, пока человек думает;
- на каждой остановке — после вопроса и после ответа человека (раздел «Остановки»);
- при запуске шага без остановки перед ним (шаги 3–7 после сбора, перезапуск шага), когда шаг уже `running` со `started`;
- после конца каждого агента, когда его строка уже в `notes.md`.

Ссылку даёт первая удачная отправка. Сразу дай её человеку отдельной строкой — в начале прогона это первая строка в чат — и запиши в `notes.md`: `ДД.ММ ЧЧ:ММ — шаг 1 — стенд: <ссылка> — скрипт — 0 — 0`.

Ошибка — одна строка `стенд: <причина>` и код 1. Запиши её событием в `notes.md`, модель — «скрипт», и иди дальше: прогон стенда не ждёт, следующая отправка пробует снова. Ошибка 403 («чужой прогон») сама не пройдёт: удали `RUN/.stand.json` и отправь снова — стенд заведёт новую страницу. Новую ссылку дай человеку и запиши в `notes.md`. Пока стенд не отвечает, на остановке давай вместо ссылки путь к локальной странице (раздел «Страница прогона»). Код 0 и строка `стенд: не влезли …` — отправка прошла без этих файлов: запиши строку в `notes.md`.

Человек сказал не слать прогон на стенд — `push_run.py` не запускай, на остановках давай путь к локальному `ui.html`.

Страница прогона открывается по ссылке без пароля — дай ссылку человеку сразу. Список всех прогонов спрашивает общий пароль команды; его даёт людям Андрей, ты его не знаешь и не спрашиваешь. В Codex отправке нужна сеть — раздел «Движки».

## Страница прогона

Человек следит за прогоном на странице стенда: шаги и их итоги, тексты файлов, журнал из `notes.md` и открытый вопрос. Дизайн один на все прогоны — `$SKILL/ui/page.html`, данные шлёт `push_run.py`. Отвечает человек в чате.

`RUN/status.json` ведёшь ты. Образец — `$SKILL/references/status-example.json`: прогон на последней остановке. Шаги, их файлы и разделы:

- `formula` 1 «Формула запроса» — `formula.md`, `input.md`; раздел «Формула»;
- `market` 2 «Кто уже это делает и рынок» — все `evidence/*.md`, `check.md`, `card.md`; разделы «Кто уже это делает» и «Боль автора: что показал сбор»;
- `segments` 3 «Сегменты» — `card.md`; раздел «Сегменты»;
- `solutions` 4 «Решения» — `card.md`; раздел «Решения»;
- `money` 5 «Деньги и отсев» — `card.md`; раздел «Деньги и отсев»;
- `test` 6 «Проверка» — `card.md`; раздел «Проверка»;
- `card` 7 «Карта возможностей» — `card.md`; разделы «Главное», «Карта возможностей», «Не знаем».

Раздел шага — поле `section`: имя раздела или список имён. Страница показывает итогом шага текст этих разделов из его файлов, когда шаг `done` или `waiting`, — копировать текст в `status.json` не нужно. Без `steps` скрипт подставит все семь шагов сам со статусом `next`.

Скелет файла:

```json
{"run": "<папка прогона>", "title": "<запрос в 3–6 словах>", "updated": "ДД.ММ.ГГГГ ЧЧ:ММ",
 "steps": [{"id": "formula", "n": 1, "title": "Формула запроса", "status": "running",
            "files": ["formula.md", "input.md"], "section": "Формула",
            "summary": "…", "started": "ЧЧ:ММ", "finished": "ЧЧ:ММ"}, "…ещё шесть шагов…"],
 "question": {"id": "q-1", "step": "formula", "text": "…", "items": ["…", "не знаю"], "asked": "ЧЧ:ММ"},
 "answers": [{"id": "q-1", "step": "formula", "text": "…", "answer": "…", "at": "ЧЧ:ММ"}]}
```

- `status` шага — `done`, `running`, `waiting` (ждёт человека), `next` или `skipped`. `summary` — первые 1–3 фразы итога, который ты даёшь в чате; у шагов 3–6 его можно не писать — страница покажет их разделы.
- `question` — `null` или вопрос; `question.step` — id шага, к которому он относится. Варианты ответа — в `items`, строка на вариант, «не знаю» последним: страница стенда показывает `text` и под ним `items`. `id` вопросов идут подряд: `q-1`, `q-2`, … Без `run` черновики ответов разных прогонов смешаются, без нового `id` черновик прошлого вопроса всплывёт в следующем.
- Стенд не отвечает — собери страницу локально и дай человеку путь `file://<абсолютный путь RUN>/ui.html`. В браузере она только показывает прогон: человек отвечает в чате.
  ```bash
  python3 $SKILL/tools/render_ui.py --run RUN
  ```

## Шаг 1. Формула запроса

Ведёшь сам, в разговоре, без агента и без поиска в сети. Цель шага — понять, что человек хочет узнать и что с этим сделает, и записать это его словами. От формулы зависит, что будет искать ресерч, поэтому ошибка здесь обходится дороже всего.

Поля формулы:
- **Что хочу понять:** «что строить» | «стоит ли строить X» | «сколько даст X».
- **Зачем:** какое решение человек примет по ответу.
- **Цель:** деньги к дате | метрика с базой сравнения («+30% оборота к контрольной группе за 6 месяцев») | цели нет.
- **Продукт:** нет | есть, платят <кто> за <что>.
- **Решение автора:** <что предлагает> | нет.
- **Для кого:** покупатель | продавец, мерчант или партнёр | оба. У двустороннего продукта две стороны — здесь решаем, с какой начинаем.
- **Что уже доказано:** звенья цепочки к прибыли, которые уже стоят на фактах из входа или ответов человека. У каждого — откуда это известно.
- **Боль:** что, по словам автора, у клиента не так, с меткой «подтверждено данными» или «только со слов автора».
- **Рынки:** 1–3 кандидата. Продавец и покупатель живут в разных странах — указываем обе: законы о продаже и о покупке разные.
- **Рамки:** что нельзя и что обязательно.

Формулу пишешь словами человека. Методология NMT работает внутри ресерча: ею агенты описывают сегменты и их работы. Форму запроса она не задаёт, и целью запроса не становится.

**Вопросы.** Прочитай вход и выпиши, на какие поля он уже отвечает. Остальное спрашивай в чате, по одному вопросу за сообщение, у каждого — 2–4 варианта ответа и «не знаю». Порядок:
1. Какой ответ человек хочет получить и что с ним сделает.
2. «Зачем?» — пока не дойдёшь до цели.
3. Контекст: продукт, решение автора, для кого, свои цифры, боль и откуда о ней известно, рынки, рамки.

Спрашивай только то, что знает один человек: цель, решение, рамки, свои факты и цифры. Кто платит на рынке, сколько там денег и кто конкуренты — не спрашивай: это ищет ресерч. Вопрос годится, если ответы «А» и «Б» поведут ресерч по-разному; иначе запиши допущение в формулу и не спрашивай. Обычно хватает 4–7 вопросов. «Не знаю» — законный ответ: поле становится «неизвестно» или допущением с пометкой.

Каждый вопрос — строка в `author-answers.md`, в `question` в `status.json` и отправка на стенд, чтобы страница его продублировала; пока вопрос открыт, шаг 1 — `waiting`. Каждый ответ — строка в `notes.md` и в `answers`, `question: null`, шаг 1 — снова `running`.

**Пересчитай числа автора** — пока задаёшь вопросы: суммы, произведения, периоды, кого считает каждое число. `14 млн × 1%` — это 140 тыс., а не 14 тыс. `5 + 14 + 6 = 25` не доказывает, что группы не пересекаются. Числа расходятся — сначала проверь, не о разных ли группах, периодах или слоях они говорят: люди и заходы, оборот и выручка. Объяснение годится, только если его дал вход или человек; не объяснилось — это вопрос. Числа во входе не правь.

**Запиши `RUN/formula.md`**, не длиннее 40 строк:

```markdown
# Формула запроса: <запрос в 3–6 словах>

<ДД.ММ.ГГГГ>. Подтвердил <имя>: «<его ответ>». | Ещё не подтверждена. | Человека нет, формула из входа.
Дата решения: <ДД.ММ.ГГГГ — только для прошлого кейса; иначе строки нет>

## Запрос словами автора
<1–3 строки; слова автора в «»>

## Формула
- **Что хочу понять:** …
- **Зачем:** …
- **Цель:** …
- **Продукт:** …
- **Решение автора:** …
- **Для кого:** …
- **Что уже доказано:** …
- **Боль:** …
- **Рынки:** …
- **Рамки:** …

## Пересчёт чисел автора
- «<число автора>» → <пересчёт>. Сходится | не сходится — <что это меняет>.

## Что получишь на выходе
<1–2 строки: какие группы клиентов, какое решение для каждой, сколько это даст, как дёшево проверить первым, и ответ «глубже», «убить» или «не знаем»>
```

Чисел нет — в разделе пересчёта строка «Чисел для пересчёта нет». Потом сверь цитаты формулы: `python3 $SKILL/tools/check_quotes.py --run RUN --formula`. Скрипт ищет каждую «цитату» в `input.md` и в ответах человека и зачёркивает те, которых там нет. Поправь зачёркнутое и неточное — слова автора дословно в «», свои слова без кавычек — и запусти снова, пока в строке «Цитаты формулы» не станет «Неточно: 0. Зачёркнуты: 0».

**Остановка.** Покажи формулу целиком — поля списком, как в разделе «Формула», — и одной-двумя фразами скажи, что человек получит на выходе. Спроси: «Формула верна? Если да — запускаю ресерч». Нет имени — тем же сообщением спроси, как записать его в журнал. Правка — новая версия `formula.md` и снова остановка. После «да» впиши во вторую строку формулы, кто и какими словами её подтвердил, и снова сверь цитаты формулы. Ресерч начинай только после «да».

**Человека нет.** Прогон прошлого кейса или проверка скилла, и отвечать некому: формулу собери из входа, где ответа нет — «не знаю» плюс допущение, с которым идёшь дальше. Допиши в `formula.md` раздел «## Вопросы, которые задали бы человеку»: не больше трёх, у каждого варианты ответа и что от ответа изменится. Остановок нет: после формулы — сразу шаг 2, после шага 7 прогон закрывается без вопроса.

## Шаг 2. Кто уже это делает и рынок

Сборщики, все параллельно, в фоне, на модели главной сессии (раздел «Движки»):
- первый — тема «кто уже это построил — у нас и у других», файл `players.md`. Он первым поиском проверяет, не выпущено ли то же самое у автора и кто делает это у других: найденный аналог может перевернуть вывод;
- по сборщику на каждый рынок из формулы — тема «рынок: <рынок>», файл `<рынок>.md`.

Продукт уже есть и клиенты платят — рынок доказан: хватит одного сборщика «кто уже это построил», он же ищет, как похожее сделали конкуренты и что им это дало, и публичные бенчмарки.

Каждому сборщику — одно сообщение:

> Рабочая папка: `<абсолютный путь папки сессии>` — все пути ниже от неё, команды запускай из неё.
> SKILL=`<абсолютный путь папки скилла>`
> Прочитай `$SKILL/references/collect.md` и выполни его. RUN=`<абсолютный путь к папке прогона>`. Тема: `<тема>`. Файл: `<имя>.md`. Имя агента для снимков: `collect-<N>`.

Второй сборщик через Codex — когда человек просит или когда сайт закрыт для главного движка: в одном прогоне reddit.com не открывался у Claude и открывался у Codex. Сообщение то же, файл `<имя>-codex.md`, имя агента для снимков `collect-codex-<N>`; как запускать — раздел «Движки».

Дождись всех. Нет файла или агент упал — перезапусти этого агента один раз и запиши сбой в `notes.md`. Потом сверь цитаты:

```bash
python3 $SKILL/tools/check_quotes.py --run RUN
```

Скрипт находит каждую цитату в `evidence/*.md` и `card.md`, ищет её в снимке и зачёркивает те, которых там нет. Итог — раздел «Сверка цитат» в `check.md`. Сложи в строке итога «Зачёркнуты» и «Ошибок формата». Сумма больше пятой части «Цитат» или «Цитат» — 0 — на такой сбор опираться нельзя: запиши это в `notes.md`, перезапусти сборщиков с худшими файлами один раз и скажи об этом человеку одной фразой.

Шаг 2 — `done`, в `summary` — что принесли сборщики, простыми словами. Остановки нет: сразу шаги 3–7. Разделы шага 2 на странице появятся, когда агент синтеза запишет `card.md`.

## Шаги 3–7. Сегменты, решения, деньги, проверка, карта возможностей

Один агент со свежим контекстом. Он читает только `formula.md` и `evidence/`, в сеть не ходит и пишет всё в `card.md`:

> Рабочая папка: `<абсолютный путь папки сессии>` — все пути ниже от неё, команды запускай из неё.
> SKILL=`<абсолютный путь папки скилла>`
> Прочитай `$SKILL/references/card.md` и выполни его. RUN=`<абсолютный путь к папке прогона>`.

На время работы агента шаги 3–7 — `running` с одним `started`. Агент сам сверяет цитаты `card.md` и правит его по сверке. Когда он закончил, проверь, что в `card.md` есть все разделы из `references/card.md` и что в разделе «Сверка цитат» в `check.md` нет строк про `card.md`. Шаги 3–6 — `done` с `finished`, шаг 7 — `waiting`.

**Остановка.** Скажи в 2–5 фразах: ответ, главная находка, с чего начать и при каком результате идти дальше или бросать. Дай ссылку на страницу прогона. Спроси: «Закрываем прогон или копаем глубже?»
- «Да», «закрываем» — прогон закончен: все шаги в `status.json` — `done` или `skipped`, строка в `notes.md`, отправка на стенд. Последним сообщением дай ссылку на страницу прогона: прогон уже на стенде, пересылать его никому не надо. Стенд так и не ответил — скажи это и дай путь к папке прогона.
- Правка карты («это не так», «посчитай с другой ценой») — новый агент шагов 3–7 с тем же сообщением и добавкой «Правка человека: «<слова дословно>»». Потом снова остановка.
- «Копай глубже по …» — один сборщик с темой словами человека, файл по теме. На время досбора шаг 2 — `running`. Потом сверка цитат, агент шагов 3–7 с добавкой «Учти новый файл `evidence/<файл>`. Правка человека: «<слова дословно>»» и снова остановка.

## Перезапуск одного шага

Шаг перезапускается на тех же входах: шаг 1 — на `input.md` и `author-answers.md`, шаг 2 — на `formula.md` и `input.md`, шаги 3–7 — на `formula.md`, `evidence/` и `check.md`. После перезапуска — строка в `notes.md`: какой шаг, что изменил и почему. Перезапуск шагов 3–7 без правки пишет `card.md` заново: прежний агент не читает, а прежняя версия остаётся на стенде. Новый прогон со шага N из старого — копируй только файлы шагов до N, а из `author-answers.md` — только вопросы и ответы до шага N. `.stand.json` не копируй: у нового прогона своя страница.

## Правила текста

- По-русски, короткими фразами, в действительном залоге.
- Формула — до 40 строк, сбор — до 150 строк на файл, `card.md` — до 140 строк и до 25 строк цитат.
- В `formula.md`, `evidence/` и `card.md` нет YAML, id правил и хэшей; английский — только в цитатах, в `I want to` и в названиях продуктов, компаний и сайтов.
- Номер снимка `src-NNN` и числа — по разделам «Строка цитаты» и «Числа» в `$SKILL/references/quotes.md`.
- Гипотеза помечена словом «гипотеза», оценка — словом «оценка» с расчётом. Неизвестное остаётся «неизвестно».
- Не выдумывай компании, цены и числа. Не нашлось — «не знаем».
- Пустой раздел шаблона — строка «нет», если шаблон не велит иначе. Разделов сверх шаблона не добавляй.

## Движки

Каждое сообщение агенту начинается двумя строками: «Рабочая папка: <абсолютный путь папки сессии>» и «SKILL=<абсолютный путь папки скилла>». Агент стартует в папке сессии и папки скилла не знает: пути `$SKILL/…` он берёт из второй строки.

Агенты идут на той модели, на которой человек запустил сессию: какую он выбрал, на той и гоняется прогон. Модель агентам не задавай и не подменяй — ни сильнее, ни дешевле. Прогоны сравнивают по главной модели из `notes.md`, и агент на другой модели ломает это сравнение и меняет цену прогона.

Claude Code: агенты — инструмент `Agent` с `run_in_background: true`, без параметра `model`: так агент берёт модель главной сессии. Codex: `spawn_agent` без `model` и `thinking`, по той же причине. Главной сессии Codex нужны поиск и сеть: человек запускает её из папки сессии командой `bash $SKILL/tools/codex-run.sh`. Без поиска и сети падают `snap.py fetch` и `push_run.py`; тогда попроси человека перезапустить Codex этим скриптом. Если в движке нет субагентов, выполняй `$SKILL/references/collect.md` по каждой теме и потом `$SKILL/references/card.md` сам, по одному, начиная каждый с чтения только его входов; `$SKILL` в них — твой путь к скиллу. Тогда запиши в `notes.md`: синтез не независим от разговора с человеком.

**Второй сборщик через Codex CLI.** Из Claude Code — командой Bash в фоне, из папки сессии:

```bash
codex --search exec -C "$PWD" --skip-git-repo-check -s workspace-write -c sandbox_workspace_write.network_access=true --json -o <scratch>/codex-<N>-last.md "<сообщение сборщика>" </dev/null > <scratch>/codex-<N>.jsonl 2>&1
```

`<scratch>` — временная папка вне `RUN`, у Claude Code — scratchpad сессии. `--search` — флаг самого `codex`, он стоит до `exec`; сеть в песочнице нужна для `snap.py fetch`. `--skip-git-repo-check` пускает `codex exec` в папку без git. Без `-m` Codex берёт модель из своего конфига — ту, что выбрал человек. Аккаунт ChatGPT в CLI может её не принять: проверь одной строкой `codex exec --skip-git-repo-check "ответь ok" </dev/null`. Не отвечает — спроси человека, какую модель Codex взять, допиши её в команду как `-m <модель>` и запиши в `notes.md`. К сообщению сборщика допиши:

> Файл другого сборщика не открывай, чужие снимки не трогай. Ничего не коммить и не пушь. Правила AGENTS.md и CLAUDE.md папки сессии к этой задаче не относятся.

Ответ сборщика — в `codex-<N>-last.md`, расход — в событии `turn.completed` в `codex-<N>.jsonl`.
